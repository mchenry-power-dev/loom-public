# Loom Public Repository Instructions

## Repository Purpose

This repository is the public, recruiter-facing technical case study for Loom™.

The private repository `loom` contains the actual production source code.

This public repository must never contain copied production source code, secrets, credentials, customer data, production identifiers, or commercially sensitive implementation details.

## Public / Private Boundary

Use the private Loom repository only as factual context for:
- product capabilities
- architecture
- engineering patterns
- testing methodology
- screenshots and product behavior
- technical decisions

Do not copy proprietary implementation code from the private repository into this repository.

When demonstrating implementation concepts, create:
- pseudocode
- simplified examples
- reconstructed technical patterns
- synthetic data

All public examples must be independently written for portfolio/documentation purposes.

## Audience

The primary audience is:
- technical recruiters
- engineering managers
- software engineers
- data/AI hiring teams
- ecommerce technology companies

The repository should demonstrate senior-level technical ownership across product engineering, systems architecture, Shopify development, automation, analytics, and operational tooling.

## Writing Style

Prefer:
- clear technical language
- concise explanations
- architecture-first thinking
- documented tradeoffs
- evidence of testing and validation

Avoid:
- exaggerated marketing claims
- excessive emojis
- badge walls
- bootcamp-style presentation
- representing roadmap features as completed functionality

## Safety

If there is any uncertainty about whether information is safe to publish, omit it or replace it with a sanitized abstraction.

Never expose:
- API keys
- tokens
- customer information
- order information
- store identifiers
- private URLs
- environment variables
- proprietary source files
- production database details
